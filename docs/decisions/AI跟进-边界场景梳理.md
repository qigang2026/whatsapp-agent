## 0. 几个基础事实（做后面所有判断的前提）

### 0.1 WhatsApp 24h 客户窗口（WA 平台机制）

参考 [ycloud 帮助文档](https://helpdocs.ycloud.com/help-center/zh/whatsapp-ji-chu/xiao-xi)：

- **自由格式消息**（free-form text）：只能在客户**最近一条消息后的 24 小时**窗口内发送
- **模板消息**（HSM）：**24 小时窗口之外**主动联系客户**必须**用预审批的 HSM 模板
- **入站消息**：客户主动发消息过来 → 窗口立即重置为 24h
- **状态通知**：`sent` / `delivered` / `read` / `failed` / `deleted` / `warning`，由 webhook 回调

### 0.2 SOP 节奏（SOP §6 跟进节奏表）

| 节点 | 动作 | 备注 |
|---|---|---|
| T0 | 新线索 | 5–15 分钟首触 |
| D+1 | 首触 24 小时无回复 | 轻量确认，不重复长介绍 |
| D+3 | 连续无回复 | 更换价值点：车型 / 金融可行性 / 预审 |
| D+7 | 多次无回复 | 礼貌收口，停止高频跟进，保留再激活入口 |

### 0.3 SOP 状态机（SOP §7.1）

```
新线索 → 首次触达 → 建立有效对话 → 确认需求 → 车型/方案引导 →
金融意向确认 → MStar 转接/预审 → 资料推进 → 审核 → 成交/暂缓/关闭/再激活
```

**结束态只有 4 种**：成交 / 暂缓 / 关闭 / 再激活

### 0.4 关键业务原则（SOP §10 检查清单）

- ❌ 不重复催促同一份资料
- ❌ 不承诺"一定获批/固定利率/零首付"
- ❌ 不机械重复已说过的内容
- ✅ 每次沟通必须产生"下一动作 + 负责人 + 时间"
- ✅ 关闭客户必须**记录原因 + 保留再激活入口**

## 1. PM 抛出的 3 个核心问题

### 问题 1：新线索 → AI 发起首联 → 客户拒绝 / 无响应

**事实拆解**

| 步骤 | AI 行为 | 24h 窗口 | HSM 是否需要 |
|---|---|---|---|
| T0 线索进入 CRM | | 窗口未开 | — |
| AI 发首联 → 用 HSM 模板（陌生 inbound）或自由文本（24h 已开）| 出站 | 客户发完 inbound 即开 | 取决于入口 |
| 客户**有回复** | 入站 | 重置为 24h | — |
| 客户**未回复** | 无 | 24h 倒计时 | — |
| 客户**明确拒绝** | 入站 | 重置 | — |

**SOP 已经定义的处理**：

| 触发 | SOP 出处 | 处置 |
|---|---|---|
| D+1 仍无回复 | SOP #50 | "Hola \[Nombre\]. Ayer vi..." 轻提醒，不重复长介绍 |
| D+3 连续无回复 | SOP #51 | "Le doy seguimiento a su plan de compra..." 换价值点 |
| D+7 多次无回复 | SOP #52 | "Como no he recibido respuesta, por ahora dejaré de darle seguimiento..." 礼貌收口 |
| 客户明确拒绝 | SOP §7.1 "关闭" 状态 | 标记关闭 + 记录原因 + 保留再激活入口 |
| 客户说 "no me interesa" | SOP §7.1 | 进入"关闭"状态，写明关闭原因 = "明确拒绝" |

**SOP 没明确写、但产品要兜底的灰色地带**：

1. 客户回复但只回 "ok" / "👍" / "gracias" —— 算有效对话还是无效对话？
   - SOP 没写。**业务问题**：这种情况在 [AI跟进中案例](file:///Users/qigangye/Mstar/WhatsApp%20Agent/%E6%94%B6%E4%BB%B6%E7%AE%B1-AI%E8%B7%9F%E8%BF%9B%E4%B8%AD-PC.html) 里 Pedro "Gracias, lo voy a pensar" 是按"低意向·用户孵化"算的。
2. AI 首联 → 客户 0 响应 → AI 隔 1 天再发 → 客户仍未响应 —— 这条线索**何时进入"失活"**？
   - SOP 给了 D+7 收口节奏，但没说**失活**这个状态本身如何定义（是 D+7 自动失活，还是销售手动？）

### 问题 2：客户主动要求"不要再联系我 / 不要骚扰我"

**事实拆解**

- 客户主动表达退出意图
- 这是**最强的负面信号**，属于"明确拒绝"范畴
- SOP §7.1 关闭状态 + §10 检查清单 "客户情绪不满" 都对应这种情况

**SOP 已经定义的处理**：

| 出处 | 话术 / 动作 |
|---|---|
| SOP #55 客户情绪不满 | "Entiendo su molestia. Voy a revisar lo que ya nos compartió antes de pedirle cualquier dato adicional..." 停止催促，人工核对 |
| SOP §7.1 关闭 | "明确不匹配/拒绝/长期无回复且本轮结束" → 停止高频联系；保留历史和再激活时间 |

**SOP 没写、但产品要兜底的灰色地带**：

1. **退出信号分级**：
   - 强："不要再联系我" / "骚扰我" / "不要再发"
   - 弱："我现在很忙" / "过几天再说" / "让我想想"
   - **强信号必须立即停止 + 关闭状态**（无争议）
   - **弱信号走 SOP #51 D+3 节奏**（无争议）
   - 灰色地带：客户说"我考虑考虑"但**之后 7 天+ 都没回** → 是"暂缓"还是"关闭"？
2. **退出话术谁来发**：
   - SOP #52 D+7 礼貌收口话术是 AI 自动发的
   - **强负面信号**（"骚扰"）的话术 SOP #55 是销售手动处理
   - **灰色地带**：客户没说"骚扰"，但语气明确负面（"别发了"），是 AI 自动回还是直接转人工？

### 问题 3：3 天后再触达 → 是否必须用 HSM 模板？

**事实拆解**

参考 ycloud 帮助文档 · 消息：

| 触发 | 24h 窗口状态 | 能否用自由文本 | 必须 HSM？ |
|---|---|---|---|
| 客户 24h 内回复过 | 开 | ✅ | ❌ |
| 客户 24h 没回复，3 天后再发 | 关 | ❌ | ✅ |
| 客户已"关闭" → 客户主动 re-engage | 重新开 | ✅ | ❌ |
| 客户 7+ 天没回 → D+7 礼貌收口 | 关 | ❌ | ✅ |

**SOP 已经定义的处理**：

| 节奏点 | 出处 | 实际是哪种消息 |
|---|---|---|
| T0 首联（陌生 inbound）| 24h 已开 | 自由文本（注意：参考 [发起新聊天](https://helpdocs.ycloud.com/help-center/zh/inbox/fa-qi-xin-liao-tian)，陌生 inbound 窗口已开）|
| T0 首联（客户留资触发）| 24h 已开 | 自由文本 |
| D+1 轻提醒 | 24h 已关 | **必须 HSM 模板**（D+1 = 24h+1 已经出窗口）|
| D+3 换价值点 | 24h 已关 | **必须 HSM 模板** |
| D+7 礼貌收口 | 24h 已关 | **必须 HSM 模板** |
| 客户主动 re-engage | 24h 重新开 | 自由文本 |

**SOP 没写、但产品要兜底的灰色地带**：

1. **D+1 / D+3 / D+7 三个节奏点的 HSM 模板是同一条还是三条？**
   - SOP 里三个场景分别给了 3 段西语文案（#50 / #51 / #52），说明是**3 条独立 HSM 模板**
   - **产品问题**：销售/老板需要在哪里看到"3 条 HSM 模板已用了几条"？
2. **HSM 模板发送失败 / 状态 failed 怎么办？**
   - ycloud 文档明确：`failed` 状态会被回调
   - SOP §10："Failed、号码异常、跨会话、顾问未接通等异常是否被单独闭环"
   - **产品问题**：failed 后多久重试？重试几次？还是标记战败？
3. **客户回复过但失活 8 天**，AI 想再激活 → **是新一条 HSM，还是用原会话窗口？**
   - SOP #53 给了"客户重新联系"的话术，但那是被动响应（客户先发）
   - **业务问题**：AI 主动 re-engage 失活 8 天的客户，是否要走"再激活 HSM"？

## 2. 全链路边界问题清单（PM 没问到的、但很可能发生的）

按线索生命周期分组。每条标注：**SOP 是否已定义 / 需要产品兜底的程度**。

| # | 场景 | SOP 定义 | 产品兜底程度 |

| F2 | 客户**已读不回**（read receipt）| ❌ 未定义 | 🟡 重要（已读不等于已看 / 已看不等于有回应）|

## 4. 产品设计侧需要回应的能力（下一步议题）

梳理完上述边界后，**产品形态**至少需要这6 块能力：

1. **状态机引擎**：CRM 字段能区分 12 个 SOP 状态 + AI 任务子状态
2. **节奏调度器**：D+1 / D+3 / D+7 + 24h 窗口倒计时 + HSM 模板选用
3. **退出信号识别器**：识别 "不要联系我" / "骚扰" / "ok/gracias" 等语义
4. **撞单 / 黑名单检测**：号码去重 + 历史拒接记录
5. **HSM 失败处理**：失败重试 + 备用通道 + 战败标记
6. **SLA / 升级机制**：handoff SLA 计时 + 升级通知
