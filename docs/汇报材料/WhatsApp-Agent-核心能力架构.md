# WhatsApp AI Sales Agent · 核心能力架构

> **目标**：定义 CAVi WhatsApp AI Sales Agent 的四大核心能力体系，为产品设计、研发排期、技术选型提供统一语言。
>
> **作者**：CAVi 产品组
> **日期**：2026-09-06
> **文档状态**：✅ 核心架构文档（v1.0）

---

## 一句话结论

> WhatsApp Agent = **一个通道 + 三个引擎**
>
> - **YCloud 通道**：WhatsApp 消息的发送与接收（纯通讯管道）
> - **HSM 引擎**：主动触达，管理所有模板消息推送
> - **AI 对话引擎**：实时响应客户消息，推进线索
> - **任务编排引擎**：管理什么时候用什么引擎、线索怎么流转

## 能力详解

---

### 能力一：YCloud 通道（通讯管道）

**定位**：WhatsApp Agent 的消息底座。负责所有消息的发送与接收，不含任何业务逻辑。

#### 技术职责

| 职责 | 说明 |
|---|---|
| **Send API** | 接收 CAVi 指令，把消息发送到 WhatsApp |
| **Webhook** | 接收 WhatsApp 回传的客户消息/状态通知 |
| **HSM 模板发送** | 调用已审批模板，把内容送达客户 |
| **连接状态** | 维护 WhatsApp 商业账号的在线状态 |

#### 协作关系

```
YCloud 通道
    ↓ 接收
AI 对话引擎（客户发消息 → AI 回复）
HSM 引擎（定时任务 → 推送模板消息）
    ↓ 发送
WhatsApp 用户
```

#### 关键约束

| 约束 | 说明 |
|---|---|
| 24h 窗口 | 客户发消息后 24h 内，CAVi 可自由回复（免费）；超时后必须用 HSM |
| 模板审批 | HSM 必须先经 Meta 审批，ycloud 负责递交 |
| 配额限制 | 日发送配额由 YCloud 管控（见 WA 平台约束文档）|
| 评级机制 | YCloud 账号评级影响消息发送优先级和配额 |

#### 不负责的事

- ❌ 不决定什么时候发消息
- ❌ 不理解客户意图
- ❌ 不生成回复内容
- ❌ 不管理线索状态

---

### 能力二：HSM 引擎（主动触达引擎）

**定位**：负责所有「主动触达」场景的消息推送。是 AI 销售 Agent 的「主动出击」能力。

#### 什么是 HSM

HSM（Highly Structured Message，模板消息）是 WhatsApp 规定的「24 小时窗口外主动触达客户」的唯一合法方式。

| 触发条件 | 是否需要 HSM |
|---|---|
| 客户发消息后 24h 内回复 | ❌ 不需要，直接发自由消息 |
| 客户超过 24h 未互动 | ✅ 必须用 HSM |
| 新线索首次触达 | ✅ 必须用 HSM |

#### 核心职责

| 职责 | 说明 |
|---|---|
| **模板内容管理** | 维护 HSM 模板库（标题、正文、变量、按钮）|
| **变量填充** | `{{customer_name}}`、`{{car_model}}` 等占位符替换 |
| **发送调度** | 按任务编排引擎的指令，在指定时机发送指定模板 |
| **状态回传** | 记录发送状态（已发送/已送达/已读/失败）|

#### HSM 的使用场景

| 场景 | 目的 |
|---|---|
| **新线索首触** | T0 时间窗口内主动打招呼，附上 CTA |
| **D+1 轻提醒** | 礼貌激活沉默线索，不重复催促 |
| **D+3 换价值点** | 换车型亮点或金融方案重新激活 |
| **D+7 礼貌收口** | 告知可随时回来，保留再激活入口 |
| **预约提醒** | 试驾/预审结果通知 |
| **优惠到期提醒** | 制造紧迫感促进转化 |

#### 自建 HSM 管理后台

ycloud 后台只能管理模板内容，无法满足销售/运营的自助配置需求。CAVi 必须自建 HSM 管理后台：

| 能力 | 说明 |
|---|---|
| 模板编辑器 | 可视化编辑，字符计数，变量映射 |
| 分类管理 | 按节点分类（首联/跟进/预审/收口）× 语言（ES/ZH）|
| 审批流程 | 草稿 → 内审 → 提交 YCloud → Meta 审批 → 就绪 |
| 版本控制 | 每次修改留档，可回滚 |
| 编排联动 | 模板关联 cadence 节点，编排引擎直接调用 |
| 使用分析 | 发送成功率、打开率监控 |

#### 与 AI 对话引擎的区别

| | HSM 引擎 | AI 对话引擎 |
|---|---|---|
| **触发方式** | 主动（我们发给客户）| 被动（客户先发，我们回复）|
| **时间限制** | 任何时候都可以 | 客户发消息后 24h 内 |
| **消息格式** | 固定模板，有变量占位 | AI 自由生成 |
| **内容控制** | 运营配置，消息内容可控 | AI 生成，内容不可完全预设 |
| **主要场景** | 首触激活、提醒、收口 | 实时答疑、意图识别、预审收集 |

---

### 能力三：AI 对话引擎（实时响应引擎）

**定位**：负责所有「被动响应」场景。是 AI 销售 Agent 的「智能应答」能力。

#### 核心职责

| 职责 | 说明 |
|---|---|
| **意图识别** | 理解客户消息的意图（问价格/要试驾/问金融/投诉/闲聊）|
| **回复生成** | 按 SOP 知识库生成个性化回复 |
| **预审推进** | 按 cadence 节点收集预审字段 |
| **对话管理** | 维护多轮对话上下文，管理对话状态 |
| **转人工判断** | 识别复杂场景，触发转人工流程 |

#### 技术架构

```
客户消息（WhatsApp → YCloud Webhook）
    ↓
意图识别层（AI 判断客户意图）
    ↓
SOP 知识库（车型知识 / 金融方案 / SOP 规则）
    ↓
回复生成层（中转平台 → LLM）
    ↓
消息输出（YCloud Send API → WhatsApp）
```

#### AI 能力边界

| AI 能做的 | AI 不能做的（转人工）|
|---|---|
| 回答车型参数、续航、价格等基础问题 | 超出车型知识库的问题 |
| 按 SOP 节奏推进线索 | 客户情绪激动/投诉 |
| 收集预审字段（引导填表）| 需要销售专业判断的复杂问题 |
| 识别高意向客户并优先跟进 | 客户明确要求转人工 |
| 多语言切换（ES/ZH）| 涉及法律/合同条款的解释 |

#### 与 HSM 引擎的协作

```
任务编排引擎
    │
    ├──→ 定时触发 → HSM 引擎 → 推送模板消息
    │
    └──→ 客户发消息 → YCloud Webhook → AI 对话引擎 → 实时回复
```

两个引擎共享同一个线索上下文，确保消息连续性：

- HSM 推送后，客户可能回复 → AI 对话引擎接管
- AI 对话结束后，线索进入沉默 → 任务编排引擎等待下一个 HSM 节点

---

### 能力四：任务编排引擎（节奏大脑）

**定位**：整个 Agent 的「大脑」。管理线索的流转节奏、节点状态、引擎调度。是 AI 销售 Agent 的「决策中枢」。

#### 为什么必须自建

YCloud Journey Builder 等通用工具的编排逻辑是：

```
触发条件 A → 发消息 B → 等 X 小时 → 发消息 C
```

CAVi 的业务编排需要：

```
触发条件 A（线索进入）
    ↓
节点 1：首联触达
    → 执行：HSM 推送（首联模板）
    → 等待：客户是否在 2h 内回复？
        ├── 是（有效对话）→ 流转到节点 2
        ├── 否（gracias/ok）→ AI 对话引擎接管意图识别
        └── 否（24h 无回复）→ 进入节点 1.1 轻提醒
    ↓
节点 2：意向激活（D+1）
    → 执行：HSM 推送（D+1 模板，含新价值点）
    → 条件判断：意向等级 ≥ B 级？
        ├── 是 → 流转到节点 3
        └── 否 → 继续跟进或降级
    ↓
节点 3：预审推进（D+3）
    → 执行：AI 对话引擎推送预审 H5
    → 等待：客户是否在 48h 内提交预审？
        ├── 是 → 转人工（销售跟进）
        └── 否 → 发送 HSM 催填
    ↓
节点 N：礼貌收口（D+7）
    → 执行：HSM 推送（收口模板）
    → 结束：线索进入「暂缓」状态，保留再激活入口
```

这种颗粒度的编排逻辑，通用工具无法实现。

#### 节点配置结构

每个 cadence 节点包含：

```json
{
  "node_id": "d1_followup",
  "node_name": "D+1 轻提醒",
  "trigger_condition": {
    "type": "time_after_last_action",
    "hours": 24,
    "exclude_if": ["customer_replied", "in_manual_handover"]
  },
  "execution": {
    "engine": "hsm",
    "template_id": "d1_reminder_es",
    "variables": {
      "customer_name": "{{name}}",
      "car_model": "{{interested_car}}"
    }
  },
  "transitions": [
    {
      "condition": "customer_replied_within_2h",
      "target_node": "intent_activation"
    },
    {
      "condition": "no_reply_within_24h",
      "target_node": "d3_activation"
    },
    {
      "condition": "customer_uninterested",
      "target_node": "graceful_close"
    }
  ],
  "sla": {
    "max_attempts": 3,
    "escalation_after": "72h_no_response"
  }
}
```

#### 线索状态机

```
新线索入队
    ↓
[AI 跟进中] ←→ [销售跟进中]
    ↓           ↓
[等待预审]   [预审中]
    ↓           ↓
[转人工] ──────────→ [成交 / 暂缓 / 关闭]
                              ↓
                         [再激活]
```

## MVP-1 优先级

| 能力 | MVP-1 是否包含 | 说明 |
|---|---|---|
| **YCloud 通道** | ✅ 必须 | 所有消息的发送接收底座 |
| **HSM 引擎** | ✅ 必须 | 新线索首触 + D+7 收口 |
| **AI 对话引擎** | ✅ 必须 | 24h 窗口内实时响应 |
| **任务编排引擎** | ✅ 必须 | cadence 节点 2-3 个（D+1 / D+3 / D+7）|
| **HSM 管理后台** | 🔲 MVP-2 | MVP-1 先用固定模板 |
| **状态机可视化** | 🔲 MVP-2 | MVP-1 用数据库状态字段 |
