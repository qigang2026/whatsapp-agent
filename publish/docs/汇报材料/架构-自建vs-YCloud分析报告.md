# 自建 vs YCloud 能力分析报告

> **目标**：向领导说明为什么 CAVi WhatsApp AI Sales Agent 必须自建「任务编排引擎」和「统一客服收件箱」，而不是直接使用 YCloud 自带的 Journey Builder / Bot Flow / Inbox。
>
> **作者**：CAVi 产品组
> **日期**：2026-09-06
> **文档状态**：待领导评审 ⭐ 重点文档

---

## 一句话结论

> **YCloud = 发件箱 + 收件箱（纯 WhatsApp 通讯管道）。**
> **CAVi = 编排逻辑 + AI 决策 + 状态机 + 销售工作台（业务核心竞争力）。**
> **两边通过 HTTP API 解耦，互不锁定。**

---

## 一、背景问题

CAVi 需要一个「AI 销售 Agent」，功能包括：

1. **任务编排**：按 SOP 节奏（D+1 轻提醒 → D+3 换价值点 → D+7 礼貌收口）自动跟进线索
2. **统一客服收件箱**：AI / 销售协同，线索归属清晰，SLA 兜底
3. **AI 对话能力**：理解客户意图、生成个性化回复、收集预审信息

YC loud 本身是一个完整的 WhatsApp 商业平台，提供了：

- Journey Builder（用户旅程/自动化流程）
- Bot Flow Builder（机器人对话流）
- AI Agent（内置 AI 能力）
- Inbox + Assignment（统一收件箱 + 分配）

**所以问题来了**：这些 YCloud 自带能力，我们能直接用吗？

---

## 二、YCloud 能力分层分析

### 2.1 能直接用的（✅ 纯管道层）

| YCloud 能力 | 我们怎么用 | 原因 |
|---|---|---|
| **Send API**（发消息） | 直接调用 POST | 纯通道，只负责把消息送到 WhatsApp |
| **Webhook 接收** | 监听 inbound + status | 纯通道，只负责把客户消息回调给我们 |
| **HSM 模板发送** | 调用 ycloud Send API 发送已审批模板 | 发送通道必须用 ycloud，无法绕过 |

**这三项是纯通讯能力，没有业务逻辑，任何企业用 WhatsApp API 都必须依赖这个管道。**

### 2.2 不能直接用的（❌ 业务逻辑被锁死）

| YCloud 功能 | 为什么不直接用 |
|---|---|
| **Journey Builder** | 1. workflow 是黑盒，无法注入我们自己的 AI 决策逻辑<br>2. 我们的节奏编辑器需要 CAVi 特有字段（意向等级、预审进度、金融方案）<br>3. 出口规则 / 分支条件需要与 CAVi CRM 状态机深度耦合 |
| **Bot Flow Builder** | 无法接入我们自己的 AI 模型 |
| **AI Agent** | 我们的 AI 是自己的（中转平台），不是 YCloud 的 |
| **Inbox + Assignment** | YCloud 收件箱不知道线索的「预审进度 / 金融方案 / 归属销售」 |
| **HSM 模板管理** | ❌ **必须自建**：ycloud 后台无法让销售/运营自助配置模板，详见 §四 |

---

## 三、核心矛盾：AI 必须是自己的

这是最关键的决策点。

### 3.1 为什么 AI 不能用 YCloud 的？

| 维度 | YCloud AI | CAVi 自建 AI |
|---|---|---|
| **模型选择** | YCloud 指定模型，无法更换 | 可自由选择（GPT-4o / Claude / 本地模型）|
| **车型知识** | 通用客服，不知道 XPENG G6 / 续航参数 / 金融方案 | 我们训练/微调的车型知识库 |
| **SOP 理解** | 不知道我们的 D+1/D+3/D+7 节奏 | 深度理解 SOP，能按节奏执行 |
| **数据主权** | 对话数据在 YCloud | 所有数据在我们自己系统 |
| **成本控制** | YCloud 定价 | 我们跟中转平台谈的价格 |
| **合规** | YCloud 服务器 | 墨西哥市场数据合规（部分数据不出境）|

**结论**：AI 是 CAVi 产品的核心竞争力之一。我们不能把 AI 交给 YCloud——否则 YCloud 可以随时涨价、换模型、甚至把我们的客户对话数据用于训练竞品。

### 3.2 为什么任务编排必须自己建？

YC loud Journey Builder 的节奏逻辑是「通用」的：

```
触发条件 A → 发消息 B → 等 X 小时 → 发消息 C
```

但 CAVi 的节奏是「业务深度定制」的：

```
触发条件：线索意向等级 = "中"，预审进度 = 3/8，车型 = XPENG G6，
         客户上次回复 = "lo voy a pensar"，跟进次数 = 2

→ AI 决策：客户犹豫期，不重复催促，换金融可行性角度切入
→ 生成个性化消息（引用客户上次说的话）
→ 预审字段：本次尝试收集 [收入证明]（前两次都未成功）
→ 出口判断：若客户 48h 不回 → 进入失活分支；若预审完成 → 触发转人工
```

**YC loud Journey Builder 支持不了这种颗粒度的业务逻辑。**

## 四、HSM 模板管理：必须自建的理由

### 4.1 什么是 HSM？为什么重要？

HSM（Highly Structured Message）是 WhatsApp 规定的「24 小时窗口外主动触达客户」的唯一合法方式。客户不问我们、我们主动发消息 → 必须用 HSM。

**HSM 是 AI 销售 Agent 的「弹药」**——首联、激活沉默线索、礼貌收口，全部靠 HSM。

### 4.2 现状问题：ycloud 后台管理不够用

| 现状 | 问题 |
|---|---|
| HSM 在 ycloud 后台管理 | 销售/运营要改一句话 → 找 PM → 找 ycloud → 等审批 |
| 模板内容分散 | 不知道哪些模板在用、哪些过期了 |
| 无版本控制 | 改坏了无法回滚 |
| 无法关联编排 | 模板和 cadence 节点没有联动 |
| 无审批流程 | 草稿/审核/发布没有工作流 |

### 4.3 自建 HSM 管理系统的价值

```
销售/运营 → 自建 HSM 编辑器 → 内审流程 → 提交 ycloud/meta 审批 → 模板就绪
                                            ↓
                                    编排引擎按 cadence 调用
```

### 4.4 自建 HSM 系统的能力清单

| 能力 | 说明 |
|---|---|
| **模板编辑器** | 可视化编辑，支持 `{{变量}}` 占位符，字符计数，header/footer/buttons |
| **分类管理** | 按节点分类（首联/跟进/预审/收口），按语言（ES/ZH） |
| **审批流程** | 草稿 → 内审 → 提交 ycloud → Meta 审批 → 就绪 |
| **版本控制** | 每次修改留记录，可回滚 |
| **编排联动** | 模板关联 cadence 节点，引擎直接调用 |
| **使用分析** | 发送成功率、打开率、哪个模板在用 |
| **变量映射** | `{{customer_name}}` → CRM 字段；`{{car_model}}` → 车型字段 |

### 4.5 自建 HSM vs ycloud 后台

| 维度 | ycloud 后台 | CAVi 自建 |
|---|---|---|
| 内容配置 | 运营必须进 ycloud 后台 | 在 CAVi 工作台直接编辑 |
| 审批流程 | 无内部审核，直接提交 Meta | 先内审，再提交 Meta |
| 版本管理 | 无 | 每次修改留档，可回滚 |
| 编排联动 | 模板和 cadence 分离 | 模板直接挂载到 cadence 节点 |
| 变量管理 | 手动填占位符 | 占位符自动映射 CRM 字段 |
| 权限控制 | ycloud 权限体系 | CAVi 权限体系 |

## 五、自建 vs YCloud 内置 · 对比矩阵

| 能力模块 | YCloud 内置方案 | CAVi 自建方案 | 结论 |
|---|---|---|---|
| **WhatsApp 发收消息** | ✅ YCloud Send API | ✅ 通过 YCloud | 必须用 YCloud |
| **HSM 模板管理** | ❌ ycloud 后台（功能太浅）| ✅ CAVi HSM 管理后台 | **必须自建** |
| **AI 对话** | ❌ YCloud AI | ✅ 自建 AI（中转平台）| 必须自建 |
| **任务编排/节奏** | ❌ Journey Builder（太浅）| ✅ CAVi 编排引擎 | 必须自建 |
| **统一客服收件箱** | ❌ YCloud Inbox（语义不全）| ✅ CAVi 收件箱 | 必须自建 |
| **线索归属/SLA** | ❌ YCloud Assignment | ✅ CAVi 状态机 | 必须自建 |
| **预审流程/H5** | ❌ 不支持 | ✅ CAVi H5 表单 | 必须自建 |
| **数据分析/转化漏斗** | ❌ YCloud 仪表盘（通用）| ✅ CAVi BI | 必须自建 |

**结论**：必须依赖 YCloud 的只有「WhatsApp 发收消息」这一项。其余 7 项全部需要自建。

## 六、架构分层（更新版）

```
┌─────────────────────────────────────────────────────────┐
│                    CAVi 自建层（核心价值）                 │
│                                                         │
│  ┌────────────────┐   ┌──────────────┐   ┌──────────┐ │
│  │  HSM 模板管理后台 │   │  节奏配置编辑器 │   │ 线索状态机 │ │
│  │  (模板编辑/审批) │ → │  (可视化配置)  │ → │(CRM数据) │ │
│  └────────┬───────┘   └──────┬───────┘   └──────────┘ │
│           │                   │                           │
│           │          ┌──────▼───────┐                   │
│           │          │ AI 任务编排引擎 │                  │
│           │          │ (按 cadence   │                  │
│           │          │  执行任务)     │                  │
│           │          └──────┬───────┘                   │
│           │                 │                            │
│           │          ┌─────▼─────┐                     │
│           │          │  AI 集成层 │                     │
│           └────────→ │(中转平台API)│ ← 我们自己的 AI    │
│                      │ + SOP知识库│                     │
│                      └───────────┘                     │
│                                                         │
│  ┌──────────────┐   ┌──────────────┐   ┌────────────┐ │
│  │  统一客服收件箱 │   │   线索详情    │   │ SLA + 转  │ │
│  │  AI/销售协同   │   │（含预审进度） │   │ 人工引擎  │ │
│  └──────────────┘   └──────────────┘   └────────────┘ │
└─────────────────────────────────────────────────────────┘
                           ↕ HTTP REST API
┌─────────────────────────────────────────────────────────┐
│                    YCloud（纯管道）                        │
│                                                         │
│  Send API ──→ WhatsApp     Webhook ←── inbound + status│
│  HSM Template ← 模板内容 CAVi 定（自建管理后台）          │
│                                                         │
│  ❌ Journey Builder  ❌ Bot Flow  ❌ AI Agent         │
│  ❌ Inbox  ❌ Assignment（业务逻辑锁死，不可用）          │
└─────────────────────────────────────────────────────────┘
```

### 分层原则

1. **YCloud 层**：只做 WhatsApp 协议层的事（发消息、收消息、模板审批）
2. **CAVi HSM 层**：模板内容配置、审批流程、版本管理、编排联动
3. **CAVi 编排层**：所有业务逻辑（节奏、状态机、归属、SLA）
4. **CAVi AI 层**：所有 AI 能力（对话生成、意图识别、SOP 执行）
5. **CAVi 数据层**：所有业务数据（线索、预审、销售、转化）

## 七、为什么要这样做（领导关心的三个问题）

### Q1：为什么不用 YCloud 自带的功能？省开发成本不行吗？

**可以省的是开发量，不可省的是业务深度。**

| 对比 | YCloud Journey Builder | CAVi 编排引擎 |
|---|---|---|
| 节奏颗粒度 | 小时级通用定时 | 分钟级 + SOP 条件分支 |
| 业务字段 | 无 | 意向等级、预审进度、金融方案 |
| 出口规则 | 简单条件 | 复杂多条件 + AI 决策 |
| 差异化 | 所有 YCloud 客户一样 | CAVi 卖给客户的竞争力 |

**YCloud 能做的是「发消息」，我们做的是「按 SOP 发对的消息」。这不是同一件事。**

---

### Q2：自建难度大吗？风险在哪？

| 风险点 | 应对方案 |
|---|---|
| 开发周期长 | MVP-1 只做核心路径（首联→意向识别→转人工），6-8 周可上线 |
| AI 质量不稳定 | 接入中转平台，用 GPT-4o / Claude 等成熟模型，不自己训 |
| WhatsApp 配额被限 | 严格遵守 YCloud 配额规则（见 §七），配额调度引擎已在规划 |
| 销售不用 | 产品侧做好体验，SLA 自动兜底，销售上手成本低 |

**不做自建的风险**：用 YCloud 内置能力 = 业务逻辑被锁死在 YCloud 里 = 产品没有差异化 = 随时可以被 YCloud 涨价或被竞品复制。

---

### Q3：为什么 AI 必须是自己的？

**一句话：数据是资产，模型是壁垒。**

- 我们和客户的对话数据（车型咨询、预算问题、金融疑问）是最珍贵的销售线索数据
- 这些数据不能放在 YCloud，必须在自己系统里
- 我们的 SOP 知识、车型知识是训练出来的，不是 YCloud 能提供的
- AI 的回复质量直接决定转化率，是我们产品的核心竞争力

---

## 八、YCloud 接入策略（最小依赖）

我们只依赖 YCloud 的三项能力：

| YCloud 能力 | 用途 | 锁定风险 |
|---|---|---|
| Send API | 发消息 | 低：HTTP 标准，切换 BSP 成本可控 |
| Webhook | 收消息 | 低：标准协议 |
| HSM Template | 模板消息 | 低：内容我们定，只是走 YCloud 审批通道 |

**切换成本评估**：如果未来需要换 BSP（比如换 Twilio / MessageBird），CAVi 只需改适配层，编排引擎和 AI 层完全不动。

## 十、总结

| 问题 | 答案 |
|---|---|
| YCloud 能帮我们做什么 | 发消息、收消息、模板审批（纯通讯管道）|
| YCloud 不能帮我们做什么 | HSM 管理、AI 对话、任务编排、收件箱业务逻辑、预审流程 |
| 我们为什么要自建 | 业务深度不可妥协、数据主权不可放弃、产品差异化不可没有 |
| 最大的风险是什么 | 开发周期长（8-12 周 MVP）、AI 质量不稳定 |
| 最大的收益是什么 | 产品核心竞争力在自己手里，切换 BSP 成本低，数据完全可控 |

**一句话向领导汇报**：

> CAVi 的 AI 销售 Agent 底层走 YCloud 通道（这是行业标准），但 HSM 管理、AI 能力、任务编排、收件箱全部自建。这样做是因为：YCloud 的产品是通讯工具，CAVi 的产品是销售能力——这两件事不一样，必须分开建，才能真正做出来一个卖得动的产品。
