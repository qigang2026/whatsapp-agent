# 跟进策略 Skill · 产品逻辑梳理（v0.1）

> **目的**：把"跟进策略 Skill"页面背后混在一起的两件事拆开，定义清楚后再调整原型。
>
> **触发问题**：用户反馈 `跟进策略-Skill-PC.html` 的 SOP 卡片"产品逻辑不清晰"，节奏结构和提示词配置混在一起。
>
> **作者**：AI Agent
> **状态**：草案 → 待 PM 拍板

## 1. 根本问题：两个维度被混在一起

### 1.1 当前页面结构（梳理前）

子 Tab 4 个：
- **HSM 模板**（WhatsApp 平台层的"消息模板"，需 Meta 审核）
- **SOP 节奏**（AI 主动跟进的步骤序列 + 触发时机）
- **SLA 规则**（转人工超时 / 工时配置）
- **变量字典**（HSM 与 SOP 引用的变量池）

**问题**：HSM / SOP / SLA / Variables 看起来都是"平级的规则"，但实际上：

| 维度 | 解决的问题 | 面对的人 |
|------|----------|---------|
| **HSM 模板** | "AI **用什么话术**发出去" | Meta 审核员 / 销售主管 |
| **SOP 节奏** | "AI **何时 / 按什么步骤**跟进" | 销售运营 |
| **SLA 规则** | "转人工 **多久没响应**算超时" | 销售主管 |
| **变量字典** | "HSM 和 SOP **可引用的字段**有哪些" | 系统 / 全员 |

用户指出的"SOP 卡片乱"——是因为 SOP 卡片同时想表达：
1. **节奏结构**：STEP 1 → 2 → 3 → 4 的触发条件 / 进入条件 / 退出条件（这是**业务流程**）
2. **AI 在每一步怎么说话的逻辑**：默认提示词（这是**LLM 的 prompt**）

但页面**完全没有显示 prompt 配置**——所以用户感受到"两块事情被塞进一个卡片但只展示了一块"的混乱感。

### 1.2 真正的产品逻辑（梳理后 · v0.2）

**PM 关键洞察**：提示词**不是独立的顶层模块**，而是**依附在 SOP 节点（STEP）上的配置**。
PM 配置 SOP 时的工作流是："先把节奏搭好 → 然后给每个 STEP 配提示词"。

```
┌──────────────────────────────────────────────────────────────┐
│  跟进策略 Skill                                               │
│                                                              │
│  ┌────────────────────────────────┐  ┌──────────────────┐  │
│  │ ① 节奏配置（SOP）               │  │ ② 平台配置        │  │
│  │                                 │  │  (HSM/SLA/Vars)   │  │
│  │  STEP 1 ─┬─ 触发条件            │  └──────────────────┘  │
│  │         ├─ 退出条件            │                         │
│  │         └─ 节点提示词 ← 依附在节点上                         │
│  │  STEP 2 ─┬─ 触发条件            │                         │
│  │         ├─ 退出条件            │                         │
│  │         └─ 节点提示词 ← 依附在节点上                         │
│  │  STEP 3 ...                    │                         │
│  │  STEP 4 ...                    │                         │
│  └────────────────────────────────┘                         │
└──────────────────────────────────────────────────────────────┘
```

| 配置域 | 子项 | 解决什么问题 | 谁在配置 |
|--------|------|------------|---------|
| **① 节奏配置**（SOP + 节点提示词） | 节奏名称、适用车型、触发频率、4 步 STEP（**每个 STEP 自带：触发条件 / 退出条件 / 节点提示词**）| "AI 在什么时机做什么动作，**每一步怎么说**" | 销售运营 + 内容运营 |
| **② 平台配置**（WA 平台层） | HSM 模板（Meta 审核）、SLA 转人工规则、变量字典 | "技术侧的资源" | 系统 / 销售主管 |

**关键设计原则**：
- 提示词**依附在 STEP 节点上**（不是全局独立 Skill）
- 提示词包括：角色定义、节点 prompt、敏感词兜底、Few-shot 示例、输出格式
- 平台配置（HSM/SLA/Vars）保持独立，作为"底层资源池"被 SOP 引用

## 2. 两类配置的关系（核心心智模型 · v0.2）

### 2.1 运行时序

```
新线索进入 CRM
   ↓
AI 任务引擎启动 → 加载当前节奏（SOP）
   ↓
进入 STEP 1「首次接洽」
   ├─ 触发器：满足进入条件（线索状态 = new）
   ├─ 发送 HSM：「欢迎 · 首次接洽」（来自 ② 平台配置）
   ├─ 发送时插入变量（{{customer.name}} 等，来自 ② 平台配置）
   ├─ 客户回复后，AI 用「STEP 1 节点提示词」解读意图
   └─ 满足退出条件 → 进入 STEP 2
   ...
```

**关键点**：
- SOP 节奏 = 业务流（4 个 STEP）
- 每个 STEP 自带：触发条件 / 退出条件 / **节点提示词**
- HSM / SLA / 变量字典 = 平台资源池（被 SOP 引用）

### 2.2 配置工作流（PM 视角）

PM 在页面的实际操作顺序：

1. 选 / 新建一个节奏（如「标准跟进 · 通用车系」）
2. 设置节奏的 4 个 STEP（触发 + 退出条件）
3. **点 STEP 节点 → 配置该节点的提示词**（节点 prompt / 敏感词 / Few-shot）
4. SOP 配置完成 → 在 HSM 模板、SLA、变量字典中查 / 配底层资源

## 3. 页面结构调整方案（v0.2 · 3 选 1）

### 方案 A · 节奏为主线 + 节点下钻（推荐）⭐

```
子 Tab 改为 2 个：
  1. 节奏配置（SOP）           ← 节奏列表 + 选中节奏的 4 步 STEP
       └─ 点 STEP 节点 → 侧滑 / 下钻面板：节点提示词编辑
  2. 平台配置（HSM + SLA + Vars）← 三个资源池合并
```

**优势**：
- 符合 PM "配 SOP → 给节点配提示词" 的工作流
- 2 个 tab，最精简
- 节点提示词依附节点，没有"提示词丢失"风险

**风险**：
- 平台配置 3 项合并，HSM/SLA/Variables 之间切换可能需要内嵌二级 tab

### 方案 B · 节奏 + 节点提示词同行展示

```
子 Tab 改为 2 个：
  1. 节奏配置（SOP）           ← 节奏列表 + 4 个 STEP（每个 STEP 卡片下方直接展示提示词编辑框）
  2. 平台配置                  ← 同 A
```

**优势**：所见即所得，不下钻
**风险**：单页内容过长，节奏复杂时滚动量大

### 方案 C · 4 个 tab，节奏内嵌节点

```
子 Tab 4 个：
  1. 节奏配置（SOP · 含节点提示词下钻）
  2. HSM 模板
  3. SLA 规则
  4. 变量字典
```

**优势**：保留当前心智，HSM 独立
**风险**：tab 数量恢复到 4 个，与"删冗余"目标有冲突

## 4. 节点提示词的内容设计（仅方案 A / B 需要）

> 这是当前原型**完全没有**的第二维度，必须重新设计。
> 提示词**依附在 STEP 节点**上，每个 STEP 自带一份。

### 4.1 节点提示词的核心字段

| 字段 | 作用 | 示例 |
|------|------|------|
| **节点 Prompt** | AI 在该 STEP 的 system prompt | "你是 Maria，AutoCava 的销售顾问。当前是 STEP 1「首次接洽」。**禁止承诺利率 / 零首付 / 一定能获批**。" |
| **输入上下文** | AI 该 STEP 要收集 / 解析的客户信息 | STEP 3：预算 / 用途 / 时间 / 试驾意向 |
| **敏感词清单** | 该 STEP 必须避免的词 + 触发动作 | STEP 3 中"利率" → 转人工 / "零首付" → 转人工 |
| **Few-shot 示例** | 客户说什么 → AI 怎么回 | STEP 2：客户：'太贵了' → AI：'Entiendo, ¿qué presupuesto manejas?' |
| **输出 schema** | AI 必须返回的结构化数据 | STEP 3 → `{budget, usage, timeline, test_drive_intent}` |

### 4.2 节点提示词与 STEP 的关系

```
                    ┌──────────────────────────────┐
                    │ 节奏：标准跟进 · 通用车系       │
                    │                              │
                    │  STEP 1「首次接洽」             │
                    │   ├─ 触发条件：新线索接入       │
                    │   ├─ 退出条件：客户已读+回复     │
                    │   └─ 节点提示词 ← 自带          │
                    │      ├─ 节点 Prompt             │
                    │      ├─ 输入上下文               │
                    │      ├─ 敏感词清单               │
                    │      ├─ Few-shot 示例           │
                    │      └─ 输出 schema             │
                    │                              │
                    │  STEP 2「用户孵化」             │
                    │   └─ 节点提示词 ← 自带          │
                    │                              │
                    │  STEP 3「预审收集」             │
                    │   └─ 节点提示词 ← 自带          │
                    │                              │
                    │  STEP 4「转人工」               │
                    │   └─ 节点提示词 ← 自带          │
                    └──────────────────────────────┘
```

**关键**：提示词**依附在节点**，不存在"提示词 Skill 全局复用"——每个 STEP 独立配。

            forbidden_words: [
              {word: "利率", action: "transfer_human"},

            fewshot_examples: [

        ...
      ]
