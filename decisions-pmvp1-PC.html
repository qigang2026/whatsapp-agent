WhatsApp AI Sales Agent · MVP-1

D1-D10 PM 决策点 → 产品设计稿

基于 SOP（销售跟进标准）+ ycloud WA 平台约束 + 25 个边界场景，整理出 10 个 PM 必须拍板的决策点。 每个决策给出 3 个候选，标注推荐项，并落到具体的 UI 设计落点。

决策点 10 个 MVP-1 阶段 配套文档 2 份
D1
客户无响应多久进入失活？
P0 · 必做
SOP 依据 D+7 礼貌收口（SOP #52）后未再回复
候选方案
  • D+7 自动失活（无人值守）
  • 销售手动标（精准但慢）
  • 看已读回执（24h 已读未回）
UI 落点 收件箱 · AI 跟进中 · 加 is-lost 灰显态 + 战败 红标签
业务影响 决定 AI 跟单流的状态机边界
来源 边界场景梳理 §3 查看原型 →
D2
客户回 "gracias / ok" 算有效对话吗？
P0 · 必做
SOP 依据 未明确 · 现有案例按 "低意向·用户孵化" 处理
候选方案
  • 有效，继续推下一步话术
  • 无效，进入失活
  • 看后续 24h 是否主动提问
UI 落点 对话详情 · 加 "客户意图" 自动识别 badge（AI 推断）
业务影响 决定 AI 话术触发条件 + 跟进效率
来源 边界场景梳理 §3 查看原型 →
D3
客户已读但 24h 不回，怎么办？
P0 · 必做
WA 事实 已读回执需客户开启；未开启只能拿到 delivered
候选方案
  • 算失活
  • 等到 D+3 再 HSM（不重复）
  • 转人工（销售主动判断）
UI 落点 对话气泡 · 加 ✓✓ 已读 标记 + "24h 未回" 提示
业务影响 决定 HSM 触发节奏，避免重复骚扰
来源 交互规则表 #24 查看原型 →
D4
客户在"禁联系名单"怎么办？
P0 · 必做
SOP 依据 SOP §7.1 关闭状态 · ycloud 文档"尊重客户请求"
候选方案
  • 系统级拦截（CRM blocklist）
  • 仅 CRM 字段标记
  • 销售审核后再决定
UI 落点 线索详情页 · 红色横幅 "🚫 黑名单客户，禁止 AI 触达"
业务影响 决定 CRM 数据模型 + 触发器位置
来源 WA 约束 §4.1 P0-1 查看原型 →
D5
HSM 模板失败重试机制
P1 · 重要
WA 事实 failed 状态会被 webhook 回调
候选方案
  • 自动重试 1 次（立即）
  • 失败转人工 + 标记
  • 标记失活
UI 落点 对话气泡旁 · 红感叹号 + "HSM 发送失败，建议人工跟进"
业务影响 决定 HSM 发送流程 + 故障兜底
来源 交互规则表 #3 查看原型 →
D6
AI 转人工 SLA 未达成
P1 · 重要
SOP 依据 SOP #54 客户要求人工后立即接管，但 SLA 值未定
候选方案
  • 升级到上级销售（30 min / 2h 阈值）
  • 通知销售主管 + AI 自动回退
  • 自动回退 AI 继续跟
UI 落点 对话头部 · 倒计时进度条 + "已超时" 红警 + 升级按钮
业务影响 决定 handoff 机制 + 升级路径
来源 WA 约束 §4.6 P2-1 查看原型 →
D7
同一客户被多个销售跟进（撞单）
P1 · 重要
业务背景 同手机号可能在留资 / inbound / 旧CRM 出现多次
候选方案
  • 销售锁单优先（最快认领）
  • 时间戳优先（先到先得）
  • 客户指定（最后跟的赢）
UI 落点 会话列表 · 加 🔒 锁单标识 + 归属人头像
业务影响 决定撞单处理 + 责任归属
来源 交互规则表 #22 查看原型 →
D8
客户撤回消息的处理
P2 · 可选
WA 事实 deleted 状态会触发 webhook
候选方案
  • 仅删除本地副本（最轻）
  • 同步到所有端
  • 询问客户意图
UI 落点 撤回气泡 · "🚫 此消息已撤回" 灰显占位
业务影响 数据同步策略
来源 交互规则表 #25 查看原型 →
D9
配额不够时怎么调度？
P0 · 必做
WA 事实 250 / 1000 / 无限三级；配额按 24h 滑动窗口
候选方案
  • MVP-1: 排队（最简单）
  • 多 WABA 分摊（成本高）
  • 智能降级（低价值暂缓）
UI 落点 AI 跟进概要 · 加 "今日配额池" 仪表盘（70% 首联 / 20% 续联 / 10% 跟进）
业务影响 决定能不能撑住大流量
来源 WA 约束 §4.4 P1-1 查看原型 →
D10
何时引入多 WABA？
P3 · 规模化
架构现状 1 个 WABA · 1000 对话/天 · MVP 完全够
候选方案
  • MVP-1 就预留（复杂）
  • 日均 > 500 再做（推荐）
  • 日均 > 1000 再做（最晚）
UI 落点 暂无（架构预留扩展点，UI 不展示）
业务影响 决定架构复杂度 + 何时重构
